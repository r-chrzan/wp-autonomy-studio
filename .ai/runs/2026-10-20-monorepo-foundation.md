## Decisions & assumptions

- npm workspaces (lockfile already npm), scope `@wpas/*`.
- Internal packages are source-only TS; Turbopack transpiles workspace packages.
- DaisyUI and shadcn/ui both define `--color-primary` etc. under Tailwind v4, so they live in
  separate root layouts (`(site)` and `(admin)`) with separate stylesheets.
- Awilix `PROXY` mode because `CLASSIC` parses parameter names, which minification breaks.
- No domain entities yet; `discovery.warnWhenNoEntities: false` so the ORM boots empty.
- The migrator is registered only in the CLI config, keeping `@mikro-orm/migrations` out of
  the Next bundle. `@mikro-orm/postgresql` is in `serverExternalPackages`.
- `/api/health` logs DB errors server-side and returns only `{status, db}`.

## Session 2 (2026-10-20): live database verification

**Outcome:** success. The spec moved to `implemented/`.

### Steps
1. The Docker runtime here is OrbStack (already running). Ran `docker compose up -d --wait db`
   and Postgres 17 came up healthy. Created gitignored `.env` and
   `packages/app/.env.local` from `.env.example`.
2. `npm run orm -w @wpas/db -- debug` reported "database connection successful".
3. Migrations. There are no entities, so `db:migration:create` reports "no changes". To
   prove the pipeline, I round-tripped a temporary `MigrationProbe` entity:
   - `migration:create` generated `create table "migration_probe" …`.
   - `migration:up` applied it. Table present, insert OK, recorded in
     `mikro_orm_migrations`.
   - `migration:down` reverted it and dropped the table.
   I then removed the probe entity, migration file and snapshot, and ran
   `db:migration:up`: success, no pending migrations. The DB holds only
   `mikro_orm_migrations`.
4. **Bug found and fixed:** `/api/health` returned 503 even with the DB up. MikroORM v7
   `MikroORM.init()` only discovers metadata and does not connect, despite its docblock, and
   `checkConnection()` returns `{ok:false, reason:"Connection not established"}` until
   `connect()` is called. Fix: `initOrm()` in `packages/db/src/orm.ts` now calls
   `await orm.connect()`.
5. Process note: an earlier `pkill -f "next start"` missed the server (its process title is
   `next-server`), so a stale server answered on port 3123. I killed it by port.

### Verification
- `npm run lint`, `npm run typecheck`, `npm run build`: all exit 0.
- Production server (`npm run start`):
  - `/` 200, `/admin` 200.
  - `/api/health` with DB up: 200 `{"status":"ok","db":"up"}`.
  - DB stopped: 503. DB restarted: 200.
  - Server booted with DB down: 503. After DB start: 200 (retry path works).
- Dev server: `/` 200, `/admin` 200, `/api/health` 200.

### Follow-ups
- Next phase: first domain entities and the initial migration (needs a new spec).
- Still open: the `braces` audit advisory, and npm install-script approvals for
